# AI 选模助手：详细使用教程

[English](USER_GUIDE.md) · [返回首页](../README.zh-CN.md)

适用于 V0.4 开源 Alpha。建议第一次先走“离线推荐 → 仅打开 → 复制需求”，确认有价值再尝试实验性自动准备。

## 1. 安装前先确认

你需要 macOS 14+，以及至少一个自己已安装、已登录的支持客户端。助手没有捆绑模型服务，不能授予付费订阅或模型权限。

- 下载：到仓库 Releases，选择标有 Alpha 的 DMG；不要把 Alpha 当成正式稳定版。
- 安装：如果 macOS 允许打开安装镜像，可将应用拖入 Applications。未公证应用可能被拦截；不要关闭系统安全保护。无法打开时可本地构建，或等待正式签名版本。
- 更新：先把原客户端未发送的需求妥善保留，再正常退出旧选模助手、替换应用并重新启动。主窗口应显示 V0.4。只替换磁盘文件不会更新旧进程。
- 本地构建：在项目目录执行 `bash scripts/test.sh`、`bash scripts/build.sh`；应用输出在 `dist/AI选模助手.app`。打包见开发说明。

## 2. 第一次设置

打开“设置 → 客户端”，检查检测到的软件与版本，启用你要使用的软件。缺少客户端时，推荐仍可能展示参考候选，但不能自动准备到未安装的软件。

在“模型库”里勾选你实际账户可用、已经纳入规则的型号。以原软件菜单为准；助手不读取账户余额，也不检查登录权限。未纳入规则的新发现型号不能直接勾选为有效任务路由。

无需 JEV Key 也可以离线使用。不要把 ChatGPT 或 Claude 的登录凭证填进 JEV Key 输入框。

## 3. 写清楚本次任务

输入“目标 + 材料 + 交付物 + 关键约束”。例如：

- `核对三份 PDF 里同一季度的数字，标出冲突，不补写不存在的数据。`
- `梳理小型库存应用的软件架构和模块边界，先不要写代码。`
- `修改客户报告排版，让已有结论更容易阅读。`
- `Translate this paragraph into concise Chinese while keeping the product names.`

输入框支持富文本粘贴、加粗、斜体、列表和自动换行。Markdown 标记按原文保留，不进行实时渲染。任务分类与交接只处理文字；粘贴图片不等于上传附件，需要时到原客户端自行添加文件。

重要资料是否能发送到外部服务，要由你判断。选择离线推荐不会把本次需求发给 JEV；在原客户端发送后，则受原服务的数据政策约束。

## 4. 推荐结果怎么看

点“推荐模型”，通常出现四张卡：第一、第二、第三、第四优先级。内置规则先列两个国际模型，再列两个中国地区模型。它们是当前政策的首选与备用，不是成功概率，也不是一份已验证的通用榜单。

每张卡包含型号、思考档位、客户端/工作区和 API 参考价。橙色 Claude 卡带访问与账号提醒；不是网络检测结果。

点选卡片后，下方横向选项让你调整工作区和思考强度。工作区由客户端决定：对话用于聊天，Work/办公侧重资料与工具，Cowork 是 Claude 的协作工作区，Code/Codex 用于编程。最终以原软件真实功能和菜单为准。

档位是该型号的规则候选；中国客户端的“客户端设置”表示不改变原有档位，不冒充 High/Max。可以打开推荐依据，查看规则理由与命中的词。

选错类型时，重写需求再推荐；不明确的复合任务会询问哪个是主要目标。离线匹配处理不了任意语义、复杂否定或未覆盖场景，手选类别是正常兜底。

## 5. 两种交接方式

### 推荐的 Alpha 起步流程：仅打开 + 复制

1. 点“仅打开”，进入选定原客户端。
2. 回到助手点“复制需求”。这会把需求文字放进剪贴板。
3. 在原软件新建空任务，手动选择型号、档位与工作区。
4. 粘贴需求，添加原文件，确认后自行发送并续聊。

这个流程不需要 macOS 辅助功能授权，不会通过选模助手代理模型推理。

### 实验性自动准备

“准备到…”需要你授予选模助手辅助功能权限。它尝试新建任务、选择菜单、核验模式/型号/档位、确认输入区为空并填入全文。所有步骤可回读确认后才显示准备好了。它没有自动发送动作。

遇到已有草稿、焦点变化、多个近似菜单项、无法回读或超时，会停止。不要根据点击过按钮或看到客户端打开就认为已准备成功；到原客户端检查。仍可退回打开与复制。

Claude 的准备与仅打开按键一次表示知悉提醒并开始动作，不再弹第二次确认。你仍要遵守原服务对地区、访问方式与账户的要求，助手不保证账号安全。

## 6. 可选 JEV 智能推荐

“设置 → JEV 连接”填写自己的 JEV API Key，保存到本机钥匙串。“测试连接”检查认证，不代表真实任务分类已验收。认证通过后再试一次无敏感信息的任务，核对结果是否合理。

智能模式会把当前需求及分类条件发送到 JEV，产生该账户的 API 用量。任务执行仍留在原桌面客户端。网络/额度/响应失败时，本次请求回退本机规则并标记来源，不静默改变你的模式偏好。

本版本没有真实 JEV 账户端到端验证记录，不能把模拟合同检查当成服务连通或分类质量证明。

## 7. 更新模型、价格与汇率

在“模型库”点“更新模型库”，或在“价格表”点“更新价格与汇率”。公开数据来自 Models.dev 社区目录，汇率来自 Frankfurter 日参考数据。请求不包含任务或 Key，使用这些更新不要求 JEV 或辅助功能权限。

- 成功：保存本机缓存，显示拉取时间与汇率观察日。
- 部分成功：只更新有效部分，明确哪一项未更新。
- 失败：保留旧数据，不伪造“今天已核实”。
- 撤销：价格页可以恢复上一份完整缓存。

新发现型号只代表公开目录有记录。核对客户端菜单、账户权限和所需工作区/档位，再更新 Markdown 规则；刷到新名字不会自动替换四卡推荐。

## 8. 正确理解价格表

表格每百万 Token 输入/输出，默认按输出价从高到低；同价比较输入价，未知项排后。中文人民币在前、英文美元在前，旁边保留另一币种对照。来源列的提示可查看参考来源，日期分为条目更新/核价日、目录拉取时间与汇率观察日。

这是 API 大概参考价：不是订阅账单、剩余次数或任务总价。汇率换算也不是美国、中国两个市场的真实报价。缓存、上下文、时段、快速模式、工具及批量费用可能不同。

如果想维护自己的参考表，可按 `Resources/APIPrices.json` 修改后导入。有效表直接应用并可撤销；恢复内置参考不等于联网核价。API 单价不会改变任务优先级。

## 9. 更新 Markdown 规则

使用 `Resources/DefaultRules.md` 或英文结构模板。在规则设置里导入/拖入文件，验证后查看变化再应用。保留稳定任务 ID，增加规则版本，可导出或回退上一版。

V2 模板包含中英文命中词、同时命中、排除词、默认工作方式/复杂度、优先级与升降档词。型号目录定义客户端、显示名称、工作区和合法档位；任务路由定义优先与备用。任意新闻或文章不能直接导入为有效规则。

改新型号时先验证真实菜单，再改型号与路由；不要只从公开目录复制名字并假设支持所有工作区/档位。V1 旧表能读取，但没有自动离线匹配条件，需要手选类别。

## 10. 快捷键、窗口与语言

默认 Control + Option + 空格。设置里点击快捷键按钮，录制一个或两个修饰键加主键；至少包含 Command、Control 或 Option。Esc 取消，冲突保留旧组合，可以恢复默认。

主窗可以最小化、关闭后保留进程，并从 Dock、菜单栏或快捷键再打开。设置应位于主窗之前；这些 V0.4 窗口行为仍需实机验收。若没有出现新界面，先退出旧进程重开，检查标题版本。

EN/中文与主题按钮切换不应清空当前任务和所选型号；系统主题在设置中选择。别把没有保存的输入框当成跨进程任务存储，退出前自行保留重要文字。

## 11. 常见问题

| 现象 | 处理 |
|---|---|
| 推荐没有对应账户可用型号 | 查看菜单并取消不可用项；修改规则或选择备用，不能从价格表推断权限。 |
| 目录更新后四卡没变 | 正常：目录与业务路由分开，需要验证并更新规则。 |
| 准备失败 | 检查辅助功能、目标软件已登录、当前项目和空任务；用仅打开与复制。 |
| 中文任务没有匹配 | 明确主要交付目标，手选类型或扩充规则词组。 |
| JEV 失败但仍有推荐 | 看来源标记；这是离线回退，不是云端已成功。 |
| 价格缺失或更新失败 | 保留旧价/汇率，未知项标为待核实；稍后再试或导入你的表。 |
| Dock/最小化/设置层级仍旧 | 正常退出旧版后启动 V0.4；提交匿名环境信息，别发布业务输入截图。 |
| macOS 阻止下载的应用 | Alpha 未公证。使用本地构建或等待已签名版本，不关闭系统安全。 |

## 12. 反馈怎么提交

通过 GitHub Issues 提供 macOS 版本、芯片、助手版本、目标客户端版本、匿名任务、预期与实际结果。说明使用的是离线、JEV、手动交接还是自动准备。不要附 Key、聊天历史、客户文件或账户截图。

若涉及凭证或严重安全缺陷，不要在公开 Issue 贴细节，先按 [SECURITY.md](../SECURITY.md) 联系维护者的私下报告入口。
