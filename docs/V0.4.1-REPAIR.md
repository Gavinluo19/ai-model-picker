# V0.4.1 recommendation repair

## Flow

Describe work → choose AI or offline → classify → show four model priorities. Product/web analysis routes through research; the purpose of developing a product does not imply code execution.

## Exceptions and states

Working → recommended, needs one choice, or error. A successful JEV response that needs clarification is not a connection error. Category clarification offers up to three plausible categories and Other; work-mode clarification preserves the original category and complexity. A real service error displays its sanitized reason and attempts offline classification. Unknown/offline no-match tasks ask the user rather than guessing. Cancellation retains input and cannot apply a stale result.

## Permissions

JEV uses the configured key and official host only. Offline mode sends no task. Existing Keychain entries, preferences and imported Markdown are preserved. No execution-provider API is called. This patch does not add system permissions or automatically send a task to another client.

## Acceptance

144 local checks pass, including original task, held-out product-analysis wording, negations, ambiguous combined goals, category candidates, work-mode clarification and existing cancellation/network contracts. Live JEV returned HTTP 200 and classified the original request as research, discussion, confidence 0.99 with no clarification. Test account and key are never included in source or artifacts.

## Diagnostics

Record source, rule version and outcome (candidate, needs_category, needs_surface, fallback) only; never task text, credentials or raw provider errors. Existing event logs remain local.

## Limits

Keywords cannot understand all natural language. Genuine ambiguity still needs a choice. Imported custom rules are not silently overwritten; users can import the updated template. Live success on one Mac does not prove network or model availability for all accounts. This patch does not validate desktop handoff, Intel execution, or Apple notarization.
